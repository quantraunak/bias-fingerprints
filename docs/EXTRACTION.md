# What reliable relation extraction from SEC filings actually costs

Six extractor configurations, scored against one annotated sample with auditable
negatives, on hardware a single person owns. The question is not "can an LLM
read a 10-K" -- it can -- but *which* model, at what latency, fails in which
specific way, and whether any point on that frontier is good enough to build a
graph from.

The measured table is `extraction_table.md`, regenerated by
`scripts/benchmark_table.py` from cached responses. This document is the reading
of it.

## Why this is the result

The study this pipeline was built for -- whether returns propagate along
supply-chain links -- is a replication of an effect established in 2008, and
`HYPOTHESIS.md` demotes it accordingly. The extraction measurement is not a
by-product of that study. It is the part that was not already known, it is fully
measured, and it cost no compute beyond what the pilot already spent.

## The benchmark, and why its negatives matter

**Benchmark v2**: 10 filings, 55 links, **5 annotated empty on purpose**, 2
naming ten or more counterparties.

The five empty filings are the design decision that makes the rest work. They
are not filings that mention nobody -- they are rich-looking and genuinely
empty. First Solar names eleven companies, every one inside an executive
biography. Qualcomm names Veoneer, Arriver, SSW Partners, Magna, PwC and the
European Commission: acquisitions, transaction counterparties and a regulator.
Every excluded name is listed in `gold_exclusions.md` with the rule that
excluded it, so the negatives are auditable rather than implicit.

Benchmarks for this task usually publish positives only, which makes precision
unfalsifiable: a model that emits plausible company names scores well because
nothing in the reference says which names should have been rejected.

That design choice is now justified empirically rather than on principle:

| | F1 range | false positives on the five empty filings |
|---|---|---|
| usable extractors | 0.46 – 0.86 | **2 – 3** |
| unusable extractors | 0.56 – 0.65 | **26 – 27** |

The two groups overlap on F1 and separate by an order of magnitude on hard
negatives. Llama 3 8B scores F1 0.646 -- respectable, mid-table -- while
emitting 27 false links on filings that disclose no relationship at all. Half of
all filings disclose nothing, so that behaviour makes it unusable at corpus
scale, and aggregate F1 does not say so.

## Three findings

### 1. Reasoning buys direction, not coverage

Disabling reasoning on Qwen 3 32B costs 0.30 F1, and the damage is structural
rather than diffuse:

| Qwen 3 32B | F1 | FP on empty filings | direction errors |
|---|---|---|---|
| reasoning on | 0.857 | 2 | **0** |
| reasoning off | 0.558 | 26 | **8** |

Direction errors are the same counterparty extracted with the relation
reversed -- Hon Hai, Quanta and Siliconware recovered from NVIDIA's filing and
labelled `customer` rather than `supplier`. These are worse than misses. A
missed edge costs coverage; an inverted edge puts a real return series on a
backwards relationship and propagates with the wrong sign, and no downstream
diagnostic flags it. Reasoning eliminates them entirely on this sample.

The reasoning-off configuration also returns *more* links than reasoning-on --
81 against 53 on the twelve filings held in both caches. Counting links would
have selected exactly the wrong configuration.

### 2. The mixture-of-experts model fails only on length

Qwen 3 30B-A3B activates roughly 3B of 30B parameters per token. Decode on this
hardware is memory-bandwidth-bound -- every generated token reads the full
weight set -- so it runs at **13s per filing against the 32B's 270s**, a 20x
speedup, at F1 0.792.

The 0.065 deficit is not spread across the sample. It is entirely in one place:

| filings naming | Qwen 3 32B recall | 30B-A3B recall |
|---|---|---|
| 1-9 counterparties | 0.882 | **1.000** |
| 10 or more | 0.789 | **0.658** |

On short lists the MoE is perfect and beats the dense model. On the two filings
naming ten or more it drops a third, losing NVIDIA's entire outsourced-assembly
chain -- Advanced Semiconductor Engineering, Hon Hai, Siliconware, King Yuan,
Unimicron, Ibiden, Nanya. It is not a worse extractor. It is an extractor that
truncates enumerations.

That is a testable hypothesis rather than a conclusion: if the deficit is
length, splitting long passages so each call sees fewer candidate names should
close it, at 13s per filing. **Not yet run.** If it holds, the corpus becomes a
seven-hour job instead of a five-day one, and the cost frontier below collapses.

### 3. Parameter count is the wrong axis

Qwen 3 14B is the cheapest configuration that keeps precision respectable
(0.783) and is nonetheless the worst overall, because its recall on
enumerations is **0.158** -- it finds roughly one link in six on the filings
that name the most. Those filings are where a link graph's density comes from,
so the model fails hardest exactly where it would matter most.

Ranking by size, 8B < 14B < 30B < 32B, does not predict the ranking by F1:
0.646, 0.462, 0.792, 0.857. The 8B model beats the 14B on F1 while being
unusable on hard negatives. Neither aggregate captures the behaviour that
decides usability.

## The cost frontier

| use | configuration | cost |
|---|---|---|
| build a graph you intend to trade on | Qwen 3 32B, reasoning on | 270s/filing |
| screen or triage at scale | Qwen 3 30B-A3B | 13s/filing, expect truncated lists |
| anything | *not* an 8B model | 27 false links on filings disclosing nothing |

For the corpus in this project -- 2,364 filings -- that is 177 hours against 8.5
hours. The quality difference is 0.065 F1, concentrated in long enumerations.

## Limitations

Stated plainly, because they bound what the table above can claim.

- **Ten filings.** Wide confidence intervals on every number. Differences of a
  few points of F1 between adjacent configurations are not resolvable; the
  order-of-magnitude gaps (hard negatives, enumeration recall) are.
- **One annotator, no inter-annotator agreement.** The annotation rules in
  `SPECIFICATIONS.md` are written down and the exclusions are auditable, which
  makes the sample reproducible, but not independently validated. This is the
  most important gap.
- **One prompt.** Every configuration runs prompt v2 (E3). Model and prompt are
  not separated, so a result here is a statement about this model *with this
  prompt*, not about the model.
- **One task and one domain.** US 10-K filings, customer/supplier/partner
  relations. Nothing here transfers to other filing types without measurement.
- **Latency is hardware-specific.** M3 Max, 36GB, Q4_K_M quantisation, Ollama.
  The *ratios* should survive a hardware change; the seconds will not.

## What would make this citable

In order of value per hour spent, none of it requiring GPU beyond what is
already spent:

1. **Benchmark to ~100 filings.** The single biggest gap. `scripts/sample_gold.py`
   draws the sample; annotation is human time.
2. **A second annotator on 20% of the sample**, with agreement reported.
   `scripts/annotator_agreement.py` computes it.
3. **Run the passage-splitting experiment** on the MoE. It is cheap and it is
   the one open question the data actually poses.
4. **Separate prompt from model** on at least one pair, so E3's contribution is
   measurable rather than assumed.
